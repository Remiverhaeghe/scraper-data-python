@001
Q: Quel rôle joue la JVM dans l'exécution d'un programme Java ?
C: Elle exécute le bytecode des fichiers .class
W: Elle compile les fichiers .java en bytecode
W: Elle fournit l'éditeur de code du développeur
W: Elle transforme le code Java en code C
E: La JVM, machine virtuelle Java, charge et exécute le bytecode contenu dans les fichiers .class, en l'interprétant puis en compilant à la volée les parties fréquentes. La compilation des sources en bytecode est le rôle de javac, fourni par le JDK. L'éditeur relève de l'IDE. Java n'est pas traduit en C.

@002
Q: Que produit la commande javac Main.java ?
C: Un fichier Main.class contenant du bytecode
W: Un exécutable natif Main.exe pour Windows
W: Une archive Main.jar prête à distribuer
W: Un fichier Main.c compilable par gcc
E: javac compile le code source en bytecode, rangé dans un fichier .class par classe ; ce bytecode est indépendant du système et s'exécute sur toute JVM. Un exécutable natif demande un outil comme GraalVM native-image. Une archive .jar se crée avec l'outil jar ou un outil de build. Aucun code C n'est produit.

W: Ce sont deux noms pour exactement le même type

```
    }
```


@006
Q: Que vaut 17 % 5 en Java ?
C: 2
W: 3
W: 3.4
W: 0
E: L'opérateur % donne le reste de la division entière : 17 = 3 × 5 + 2, le reste vaut 2. 3 est le quotient, pas le reste. 3.4 est le résultat de la division décimale. 0 ne serait le reste que si 17 était un multiple de 5.

@007
Q: Pourquoi dit-on qu'une String est immuable ?
C: Une fois créée, son contenu ne change jamais
W: Elle ne peut pas être passée à une méthode
W: Elle ne peut pas contenir plus de 255 caractères
W: Elle doit être déclarée avec le mot-clé final
E: Les méthodes comme toUpperCase ou concat ne modifient pas la chaîne : elles en renvoient une nouvelle. Cette immuabilité permet de partager les chaînes sans risque et de les utiliser comme clés de HashMap. Une String se passe librement à une méthode. Sa longueur n'est pas limitée à 255. final concerne la variable, pas l'objet chaîne.

E: toUpperCase renvoie une nouvelle chaîne, mais son résultat n'est affecté à rien : langage garde sa valeur d'origine, « java ». langage.toUpperCase();
```
System.out.println(langage);
```

@009
Q: Que permet le mot-clé private sur un attribut ?
C: Limiter son accès à la classe qui le déclare
W: Le rendre accessible aux seules sous-classes
W: Le partager entre toutes les instances
W: L'empêcher d'être modifié après sa création
E: Un membre private n'est visible que dans sa propre classe : c'est la base de l'encapsulation, l'accès passant par des méthodes. L'accès des sous-classes correspond à protected. Le partage entre instances est le rôle de static. Empêcher la modification est le rôle de final.

@010
Q: Quelle est la différence entre une classe et un objet ?
C: La classe est le modèle, l'objet une instance
W: L'objet est le modèle, la classe une instance
W: La classe existe à l'exécution, pas l'objet
W: Il n'y en a aucune en Java
E: La classe décrit les attributs et les méthodes communs ; chaque objet créé avec new est une instance de cette classe, avec ses propres valeurs d'attributs. L'inverse n'a pas de sens. Les objets existent bien à l'exécution, en mémoire. La distinction est fondamentale en programmation orientée objet.

@011
Q: À quoi sert un constructeur ?
C: À initialiser un objet au moment de sa création
W: À détruire un objet qui n'est plus utilisé
W: À déclarer les méthodes abstraites de la classe
W: À importer les classes d'un autre package
E: Le constructeur porte le nom de la classe, n'a pas de type de retour et s'exécute à chaque new pour donner un état initial cohérent à l'objet. La destruction est gérée par le ramasse-miettes, sans destructeur explicite. Les méthodes abstraites se déclarent ailleurs. Les imports sont des instructions en tête de fichier.

@012
Q: Ces deux méthodes peuvent-elles coexister dans la même classe ?
C: Oui, c'est une surcharge : les paramètres diffèrent
W: Non, deux méthodes ne peuvent pas porter le même nom
W: Non, il faudrait des types de retour différents
W: Oui, mais seulement si l'une des deux est static
E: La surcharge autorise plusieurs méthodes de même nom si leurs listes de paramètres diffèrent par le nombre ou le type ; le compilateur choisit selon les arguments. Le nom seul ne suffit pas à les distinguer. Un type de retour différent ne suffit pas, et n'est pas nécessaire ici. static n'a aucun rapport avec la surcharge.
```
int aire(int cote) { return cote * cote; }
int aire(int largeur, int hauteur) { return largeur * hauteur; }
```

@013
Q: Que signifie static sur un attribut ?
C: L'attribut est partagé par toutes les instances
W: L'attribut ne peut plus jamais être modifié
W: L'attribut est visible depuis tout le projet
W: L'attribut est recréé à chaque appel de méthode
E: Un attribut static appartient à la classe et non à chaque objet : il existe en un seul exemplaire, partagé par toutes les instances, et s'utilise sans créer d'objet. L'interdiction de modification relève de final. La visibilité relève de public ou private. Un attribut n'est jamais recréé à chaque appel.

@014
Q: Combien de classes une classe Java peut-elle étendre directement ?
C: Une seule
W: Deux au plus
W: Autant qu'elle veut
W: Aucune, sauf Object
E: Java n'autorise l'héritage que d'une seule classe avec extends, pour éviter les ambiguïtés de l'héritage multiple ; une classe peut en revanche implémenter plusieurs interfaces. Toute classe hérite d'Object si elle n'étend rien, mais elle peut étendre une autre classe.

@015

C: En implémentant plusieurs interfaces

E: nom vaut null : appeler une méthode dessus, ici length(), lève une NullPointerException à l'exécution. null n'est pas une chaîne vide, qui aurait une longueur de 0. Rien n'est affiché. Le compilateur accepte ce code, car il ne suit pas la valeur des variables.

@017
Q: Qu'affiche ce code ?
C: A puis B puis C
W: A puis C
W: A puis B
W: B puis C
E: Le bloc try affiche A, l'exception levée est attrapée par le catch qui affiche B, puis le bloc finally s'exécute dans tous les cas et affiche C. Sauter le catch serait faux, puisque l'exception est bien de ce type. Le finally n'est jamais ignoré, sauf arrêt brutal de la JVM.
```
try {
    System.out.println("A");
    throw new IllegalStateException();
} catch (IllegalStateException e) {
    System.out.println("B");
} finally {
    System.out.println("C");
}
```

@020
Q: Qu'affiche ce code ?
C: false
W: true
W: Une NullPointerException
W: Le code ne compile pas
E: L'opérateur && évalue d'abord liste != null, qui est faux : le résultat est faux et la partie droite n'est pas évaluée, donc liste.isEmpty() n'est jamais appelé. C'est l'évaluation en court-circuit, qui évite ici la NullPointerException. Avec l'opérateur & non court-circuité, l'exception aurait été levée. Le code compile.

```
List<String> liste = null;
boolean pleine = liste != null && !liste.isEmpty();
System.out.println(pleine);
```

@021
Q: Que vaut statut avec ce code, si age vaut 17 ?
C: "mineur"
W: "majeur"
W: true
W: 17
E: L'opérateur ternaire condition ? valeurA : valeurB renvoie valeurA si la condition est vraie, valeurB sinon : 17 >= 18 est faux, statut vaut « mineur ». « majeur » serait renvoyé à partir de 18 ans. Le ternaire renvoie une des deux valeurs, pas la condition elle-même, ni l'âge.
```
int age = 17;
String statut = age >= 18 ? "majeur" : "mineur";
```

@022
Q: Que vaut n après ce transtypage ?
C: 3
W: 4
W: 3.9
W: 0
E: Le transtypage d'un double vers un int tronque la partie décimale, sans arrondir : 3.9 devient 3. Pour arrondir, on utilise Math.round, qui donnerait 4. Un int ne peut pas contenir 3.9. Le résultat n'est pas nul.
```
double prix = 3.9;
int n = (int) prix;
```
