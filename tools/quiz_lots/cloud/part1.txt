@001
Q: Associer chaque modèle de service cloud à ce que le client gère encore lui-même.
P: IaaS => système d'exploitation, logiciels et données
P: PaaS => code de l'application et données
P: SaaS => données et comptes des utilisateurs
E: En IaaS, on loue des machines virtuelles : le fournisseur gère le matériel et la virtualisation, le client tout le reste à partir du système. En PaaS, la plateforme fournit l'environnement d'exécution, le client déploie son code. En SaaS, le logiciel est prêt à l'emploi : il ne reste que les données et les comptes à administrer.

@002
Q: Une équipe veut déployer son application web sans gérer de serveur, de système ni de correctifs, en ne fournissant que son code. Quel modèle lui correspond ?
C: PaaS, comme App Service, Elastic Beanstalk ou App Engine
W: IaaS, avec une machine virtuelle à installer et à maintenir
W: SaaS, puisque l'application sera utilisée par un navigateur
W: Un serveur physique hébergé dans le centre de données du fournisseur
E: Le PaaS prend en charge système, environnement d'exécution, mise à l'échelle et correctifs : l'équipe ne livre que son code. Une machine virtuelle relève de l'IaaS et laisse le système à maintenir. Le SaaS désigne un logiciel fini qu'on utilise, pas une plateforme où l'on déploie le sien.

@003
Q: Que désigne une région chez un fournisseur de cloud comme AWS ?
C: Une zone géographique de plusieurs centres de données isolés
W: Un seul grand centre de données, unique pour tout un continent
W: Un réseau privé virtuel créé par le client dans son compte
W: Un niveau de tarification qui varie selon le pays de facturation
E: Une région, par exemple eu-west-3 à Paris, regroupe plusieurs zones de disponibilité, chacune faite d'un ou plusieurs centres de données indépendants. Le choix de la région fixe l'emplacement des données, la latence pour les utilisateurs et parfois les prix. Le réseau privé du client est un VPC, pas une région.

@004
Q: Pourquoi répartir des serveurs sur plusieurs zones de disponibilité d'une même région ?
C: Pour que la panne d'un centre de données n'arrête pas le service
W: Pour diviser le prix des machines virtuelles par le nombre de zones
W: Pour rapprocher les serveurs de chacun des utilisateurs du monde
W: Pour contourner le quota de machines autorisé dans une seule zone
E: Les zones d'une région sont alimentées, refroidies et raccordées séparément, mais reliées par un réseau rapide. Si une zone tombe, les instances des autres continuent de servir. Se rapprocher des utilisateurs du monde entier demande plusieurs régions ou un CDN, pas plusieurs zones voisines.

@005
Q: Associer chaque service de stockage objet à son fournisseur.
P: Amazon S3 => AWS
P: Blob Storage => Azure
P: Cloud Storage => Google Cloud
E: Les trois services stockent des fichiers sous forme d'objets dans des conteneurs appelés bucket chez AWS et Google, container chez Azure. On y accède par une API HTTP, sans système de fichiers à monter. Ils servent aux sauvegardes, aux fichiers statiques d'un site, aux journaux et aux données d'analyse.

@006
Q: Associer chaque service de machines virtuelles à son fournisseur.
P: EC2 => AWS
P: Virtual Machines => Azure
P: Compute Engine => Google Cloud
E: EC2 signifie Elastic Compute Cloud. Les trois services louent des machines virtuelles à la seconde ou à l'heure, avec un choix de tailles (processeurs, mémoire) et d'images système. C'est le service IaaS de base de chaque fournisseur, sur lequel s'appuient beaucoup d'autres.

@007
Q: Que signifie le modèle de responsabilité partagée du cloud ?
C: Le fournisseur sécurise l'infrastructure, le client ce qu'il y déploie
W: Le fournisseur reste seul responsable de toute la sécurité du compte
W: Le client doit lui-même sécuriser les centres de données du fournisseur
W: Les deux partagent le mot de passe administrateur du compte cloud
E: Le fournisseur répond des bâtiments, du matériel, du réseau et de la virtualisation. Le client répond de ses comptes, de ses droits d'accès, de ses données, de la configuration de ses services et, en IaaS, du système. Un bucket laissé public est une erreur du client, pas du fournisseur.

@008
Q: Pourquoi ne faut-il pas utiliser le compte racine (root) d'un compte AWS pour le travail courant ?
C: Il a tous les droits, sans restriction possible
W: Il ne peut créer aucune ressource, seulement consulter la facture
W: Il est supprimé automatiquement après trente jours d'inactivité
W: Il ne fonctionne que depuis la console et jamais avec la CLI
E: Le compte racine peut tout faire, y compris fermer le compte, et aucune politique IAM ne le restreint. On le protège par une authentification multifacteur et on le réserve à quelques tâches rares. Le travail courant passe par des utilisateurs ou des rôles IAM qui n'ont que les droits nécessaires.

@009
Q: Que permet l'élasticité d'un service cloud ?
C: Ajuster les ressources à la charge, à la hausse comme à la baisse
W: Garantir que le prix mensuel ne change jamais quelle que soit la charge
W: Déplacer les données d'un fournisseur à l'autre sans aucune migration
W: Augmenter la taille d'un disque sans jamais pouvoir la réduire
E: On ajoute des instances aux heures de pointe et on les retire ensuite, souvent automatiquement. On ne paie que ce qui tourne : c'est l'intérêt principal par rapport à un serveur dimensionné pour le pic. Le prix varie donc avec l'usage, et changer de fournisseur reste une vraie migration.

@010
Q: Que fait cette commande ?
C: Elle liste le contenu du bucket factures, préfixe 2026 compris
W: Elle crée un bucket nommé factures dans la région par défaut
W: Elle supprime les fichiers de 2026 dans le bucket factures


@011
Q: Quelle commande copie le dossier local site/ vers le bucket vitrine en n'envoyant que les fichiers modifiés ?
C: aws s3 sync site/ s3://vitrine/
W: aws s3 ls site/ s3://vitrine/
W: aws s3 mb site/ s3://vitrine/
W: aws s3 rb site/ s3://vitrine/
E: sync compare la source et la destination et ne transfère que ce qui a changé, ce qui convient pour publier un site statique. ls liste un contenu, mb crée un bucket et rb le supprime. Avec --delete, sync supprime aussi dans le bucket les fichiers qui n'existent plus en local.

@012

W: On paie un forfait fixe par mois quel que soit le nombre de serveurs
W: On paie uniquement au moment de la création de chaque ressource
W: On paie selon le nombre de personnes qui se connectent à la console
E: Une machine virtuelle est facturée à la seconde ou à l'heure, le stockage au gigaoctet par mois, le trafic sortant au gigaoctet transféré. Une ressource oubliée continue donc de coûter : arrêter les environnements de test la nuit et supprimer ce qui ne sert plus fait vite baisser la facture.

@013
Q: Une machine virtuelle de test coûte 0,10 € de l'heure. Combien coûte-t-elle sur un mois de 30 jours si elle tourne en continu ?
N: 72
U: €
T: 1
E: 0,10 € × 24 heures × 30 jours = 72 €. Si on l'arrête la nuit et le week-end, en ne la gardant que 10 heures par jour ouvré, soit environ 220 heures par mois, la facture tombe à 22 €. Les environnements de test sont la première source d'économies faciles.

@014
Q: À quoi sert un groupe de sécurité (security group) sur AWS ?
C: Filtrer le trafic entrant et sortant d'une instance, par port et par source
W: Regrouper les utilisateurs IAM qui partagent les mêmes droits
W: Chiffrer les disques des instances qui appartiennent au groupe
W: Répartir la charge entre plusieurs instances d'un même service
E: Un groupe de sécurité est un pare-feu virtuel attaché à l'instance : on autorise par exemple le port 443 depuis Internet et le port 22 depuis l'adresse du bureau seulement. Tout ce qui n'est pas autorisé est refusé. Les droits des utilisateurs relèvent d'IAM, la répartition de charge d'un load balancer.

@015
Q: Quel risque présente cette règle de groupe de sécurité ?
C: Le port SSH est ouvert à toute adresse d'Internet
W: Le port web est fermé et le site devient inaccessible
W: La base de données est exposée sur son port standard
W: Aucun : 0.0.0.0/0 désigne uniquement le réseau local
E: Le port 22 est celui de SSH et 0.0.0.0/0 désigne toutes les adresses IPv4 : n'importe qui peut tenter de se connecter, et les robots le font en permanence. On limite la source à l'adresse du bureau ou d'un VPN, ou on passe par un service d'accès comme Session Manager sans ouvrir de port.
```
Type : SSH
Protocole : TCP
Port : 22
Source : 0.0.0.0/0
```

@016
Q: Pourquoi un CDN comme CloudFront ou Azure Front Door accélère-t-il un site pour des visiteurs lointains ?
C: Il sert des copies des fichiers depuis des serveurs proches d'eux
W: Il compresse la base de données pour réduire le temps des requêtes
W: Il augmente la puissance du serveur d'origine aux heures de pointe
W: Il convertit le site en application mobile plus rapide à charger
E: Un CDN met en cache images, scripts et pages dans des serveurs répartis dans le monde. Le visiteur de Tokyo est servi depuis Tokyo, pas depuis Paris : moins de latence, et moins de charge sur le serveur d'origine. Les contenus dynamiques non cachés font toujours l'aller-retour jusqu'à l'origine.

@017
Q: Que garantit un SLA de disponibilité de 99,9 % par mois ?

W: Que le service ne tombera jamais plus de 99 secondes d'affilée
W: Que 99,9 % des données seront récupérables après une panne
W: Que le service sera remboursé intégralement à la moindre coupure
E: 0,1 % d'un mois de 30 jours représente 43,2 minutes. Le SLA est un engagement contractuel : au-delà, le fournisseur accorde un avoir sur la facture, pas un remboursement complet. Il ne dit rien de la durabilité des données, qui fait l'objet d'un autre engagement.

@018
Q: Combien de minutes d'indisponibilité par mois de 30 jours autorise un SLA de 99,95 % ?
N: 21,6
U: min
T: 2
E: 30 jours × 24 h × 60 min = 43 200 minutes ; 0,05 % de 43 200 donne 21,6 minutes. Chaque « 9 » supplémentaire divise l'indisponibilité tolérée par dix : 99,99 % ne laisse plus que 4,3 minutes par mois, ce qui impose plusieurs zones et une bascule automatique.

@022
Q: Que signifie le sigle VPC ?
C: Virtual Private Cloud, réseau privé isolé dans le cloud
W: Virtual Processing Core, cœur de processeur virtuel loué
W: Verified Public Certificate, certificat public vérifié
W: Volume Persistent Container, disque attaché à un conteneur
E: Un VPC est le réseau privé du client chez AWS ou Google Cloud ; Azure parle de VNet. On y définit des plages d'adresses, des sous-réseaux publics et privés, des tables de routage et des passerelles. Les instances y communiquent entre elles sans passer par Internet.

@023
Q: Quelle différence entre un sous-réseau public et un sous-réseau privé dans un VPC ?
C: Seul le public a une route vers Internet
W: Seul le privé peut contenir des machines virtuelles
W: Le public est gratuit, le privé est facturé à l'heure
W: Le privé n'a aucune adresse IP, même interne
E: Un sous-réseau est public quand sa table de routage envoie le trafic vers Internet par une passerelle Internet. On y place le load balancer ou un bastion. Les serveurs d'application et les bases vont dans des sous-réseaux privés, injoignables depuis Internet ; ils sortent si besoin par une passerelle NAT.

@026
Q: Que fait cette politique IAM attachée à un utilisateur ?
C: Elle permet de lire les objets du bucket rapports, sans rien y écrire
W: Elle donne tous les droits sur tous les buckets du compte
W: Elle permet d'écrire dans le bucket rapports, sans le lire
W: Elle rend le bucket rapports public pour tout Internet
E: s3:GetObject autorise le téléchargement des objets, et la ressource arn:aws:s3:::rapports/* limite le droit aux objets de ce bucket. Aucune action d'écriture comme s3:PutObject n'est accordée. La politique s'applique à l'utilisateur qui la porte, elle ne rend rien public.
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::rapports/*"
  }]
}
```

@027
Q: Pourquoi cette politique ne permet-elle pas de lister le contenu du bucket rapports ?
C: Lister exige s3:ListBucket sur le bucket, pas sur ses objets
W: Le mot Allow doit être écrit en minuscules pour être reconnu
W: La version 2012-10-17 est trop ancienne pour le service S3
W: Un utilisateur IAM ne peut jamais lister le contenu d'un bucket
E: s3:ListBucket porte sur la ressource arn:aws:s3:::rapports, sans /*, alors que s3:GetObject porte sur les objets arn:aws:s3:::rapports/*. Il faut donc deux déclarations, une par ressource. La version 2012-10-17 est la version actuelle du langage des politiques, à utiliser telle quelle.
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject", "s3:ListBucket"],
    "Resource": "arn:aws:s3:::rapports/*"
  }]
}
```

@034

@035
Q: Que fait cette règle de cycle de vie sur un bucket de journaux ?
C: Elle archive les journaux après 30 jours et les supprime après un an
W: Elle supprime les journaux après 30 jours et les archive après un an
W: Elle copie les journaux dans un autre bucket tous les 30 jours
W: Elle chiffre les journaux après 30 jours avec une clé tournante
E: La transition fait passer les objets du préfixe logs/ en classe Glacier 30 jours après leur création ; l'expiration les supprime au bout de 365 jours. On paie ainsi le prix fort seulement le premier mois, puis presque rien, et les journaux ne s'accumulent pas indéfiniment.
```json
{
  "Rules": [{
    "Filter": {"Prefix": "logs/"},
    "Status": "Enabled",
    "Transitions": [{"Days": 30, "StorageClass": "GLACIER"}],
    "Expiration": {"Days": 365}
  }]
}
```

W: az storage create --name rg-demo --location francecentral
E: Sur Azure, chaque ressource appartient à un groupe de ressources, qui sert à les gérer, les facturer et les supprimer ensemble. az group create le crée dans une région ; az group list liste les groupes existants. Supprimer le groupe supprime toutes les ressources qu'il contient, pratique pour un environnement de test.

@041
Q: Sur Azure, à quoi sert un groupe de ressources ?
C: Regrouper des ressources d'un même projet pour les gérer et les supprimer ensemble

E: Un groupe de ressources rassemble par exemple l'application, sa base et son stockage. On y attribue des droits, on suit son coût, et sa suppression nettoie tout d'un coup. Les ressources d'un groupe peuvent être dans des régions différentes ; la répartition de charge est le rôle d'un load balancer.

@046
Q: Qu'est-ce qu'un instantané (snapshot) d'un disque de machine virtuelle ?
C: Une copie à un instant donné, qui permet de restaurer ou recréer le disque
W: Une capture d'écran de la console de la machine virtuelle

@048

@049
Q: Que fait cette commande ?
C: Elle crée un lien de téléchargement valable une heure
W: Elle rend le bucket public pendant une heure, puis le referme
W: Elle copie le fichier dans un bucket public pendant une heure
W: Elle supprime le fichier une heure après son téléchargement
E: Une URL présignée contient une signature calculée avec les droits de celui qui la génère : quiconque a le lien peut télécharger cet objet jusqu'à l'expiration, ici 3600 secondes. Le bucket reste privé et les autres objets inaccessibles. C'est la façon propre de partager un fichier ponctuellement.

```
aws s3 presign s3://exports/clients-2026.csv --expires-in 3600
```
