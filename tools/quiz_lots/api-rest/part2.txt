E: Un JWT est vérifié localement par l'API, sans interroger personne : il ne peut pas être révoqué en cours de vie. On vise 5 à 15 minutes pour le jeton d'accès ; l'introspection auprès du serveur d'autorisation reste possible pour les opérations sensibles.

Q: Plusieurs API vérifient les jetons d'un même serveur d'autorisation. Pourquoi préférer RS256 ou ES256 à HS256 ?
C: Les API vérifient avec la clé publique sans pouvoir fabriquer de jetons
W: RS256 produit des jetons plus courts
W: HS256 n'est pas pris en charge en Python
W: RS256 chiffre le contenu du jeton, qui devient illisible pour les clients
E: Avec HS256, le même secret signe et vérifie : chaque API qui le détient pourrait émettre des jetons. Avec une paire de clés, les API lisent les clés publiques sur l'adresse JWKS du serveur et choisissent la bonne grâce au champ kid, ce qui permet la rotation.

@095
Q: Pourquoi une pagination par curseur opaque (?apres=eyJpZCI6MTAwfQ) plutôt qu'un paramètre ?apres_id=100 exposé tel quel ?
C: Le serveur peut changer le tri ou la forme du curseur sans casser les clients
W: Un curseur opaque est chiffré par le serveur et protège ainsi la base des injections SQL
W: Les entiers sont interdits dans les URL
W: Le curseur opaque dispense de trier côté base de données
E: Le client renvoie le curseur sans l'interpréter. Le jour où le tri passe à (date, id) pour départager les égalités, seul le serveur change. L'opacité n'est pas une sécurité : le curseur reste à valider comme toute entrée.

@096
Q: Une API permet à ses clients d'enregistrer l'URL de leur webhook. Quel contrôle est indispensable avant d'y envoyer des requêtes ?
C: Refuser les adresses internes après résolution DNS, pour éviter une SSRF
W: Vérifier que l'URL se termine par .json
W: Limiter l'URL à 50 caractères
W: Exiger le port 80
E: Sans ce contrôle, un client déclare http://169.254.169.254/ ou http://10.0.0.5:8080/admin et fait appeler par le serveur des services internes. La vérification se fait au moment de l'envoi, sur l'adresse réellement résolue, pour déjouer le changement de DNS.

@097
Q: En production derrière la passerelle, l'en-tête Location des créations pointe vers http://10.0.3.17:8080/commandes/1789. Que corriger ?
C: Lire X-Forwarded-Host et X-Forwarded-Proto, transmis par la passerelle déclarée de confiance
W: Écrire l'adresse publique en dur dans chaque contrôleur
W: Supprimer l'en-tête Location
W: Passer la passerelle en HTTP pour que les deux adresses correspondent
E: L'application ne voit que la connexion de la passerelle. On lui fait lire les en-têtes transmis (Forwarded, RFC 7239), mais seulement depuis l'adresse de la passerelle, sinon un client pourrait les falsifier : server.forward-headers-strategy en Spring, --proxy-headers et --forwarded-allow-ips avec uvicorn.

@098
Q: Comment annoncer aux clients qu'une route v1 sera retirée le 30 juin 2027 ?
C: En-têtes Deprecation et Sunset dans les réponses, et annonce dans la documentation
W: Renvoyer 410 Gone dès aujourd'hui
W: Ralentir volontairement la route
W: Changer son URL sans prévenir pour forcer la migration
E: Sunset (RFC 8594) donne la date de retrait, Deprecation signale que la route est déconseillée. Les journaux, ventilés par clé ou par client, montrent qui appelle encore la v1 : on les contacte avant la date au lieu de découvrir les dégâts après.

@099
Q: Associer chaque code de statut moins courant à sa situation.
P: 207 Multi-Status => Lot traité en partie, un statut par élément
P: 410 Gone => Ressource retirée définitivement
P: 415 Unsupported Media Type => Content-Type non accepté
P: 428 Precondition Required => If-Match exigé mais absent
E: Pour un import de 500 articles dont 3 en erreur, répondre 200 ou 400 pour le tout ne dit rien d'utile : un statut par ligne permet au client de ne renvoyer que les lignes rejetées. 410 dit au client d'arrêter de chercher, là où 404 laisse un doute.

@100
Q: Une API de GMAO met 6 s à renvoyer les ordres de travail. Les journaux SQL montrent une requête pour la liste puis une par ordre pour lire sa machine. Quel correctif côté serveur ?
C: Charger les machines en une seule requête, par jointure ou avec IN
W: Ajouter Cache-Control: no-store
W: Renvoyer la réponse en XML
W: Porter à 30 secondes le délai d'attente du client
E: C'est le N+1 de l'ORM : le chargement paresseux de la relation déclenche une requête par ligne. JOIN FETCH en JPA, selectinload avec SQLAlchemy ou Include avec Entity Framework règlent le problème ; activer le journal SQL en développement le révèle tôt.
