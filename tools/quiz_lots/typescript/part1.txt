@001
Q: Qu'est-ce que TypeScript ?
C: Un sur-ensemble typé de JavaScript
W: Un moteur d'exécution qui remplace Node.js
W: Un framework d'interfaces web concurrent de React
W: Un langage compilé en code machine natif
E: TypeScript ajoute des types statiques à JavaScript ; le compilateur tsc les vérifie puis produit du JavaScript ordinaire. Les types disparaissent à l'exécution : ils servent à détecter les erreurs avant, et à l'autocomplétion dans l'éditeur.

@002
Q: Que signale le compilateur sur ce code ?
C: Un nombre n'est pas assignable au type string
W: Pas d'erreur, TypeScript convertit 42 en "42"
W: Une erreur à l'exécution
W: Un avertissement de style ignoré à la compilation
E: La variable est annotée string : lui affecter un nombre est refusé dès la compilation, avant tout lancement. C'est le principal intérêt de TypeScript : une erreur de type est trouvée dans l'éditeur, pas par un utilisateur.
```typescript
let nom: string = "Léa";
nom = 42;
```

@003
Q: Associer chaque type de base à un exemple de valeur.
P: string => "Lille"
P: number => 3.14
P: boolean => false
P: string[] => ["a", "b"]
E: number couvre entiers et décimaux, comme en JavaScript ; bigint existe pour les très grands entiers. Les tableaux s'écrivent string[] ou Array<string>. Un tableau de longueur et de types fixés est un tuple : [string, number].

@004

@005
Q: Pourquoi éviter le type any ?
C: Il désactive toute vérification sur la valeur
W: Il rend le code plus lent à l'exécution
W: Il est interdit dans les fichiers .ts
W: Il oblige à écrire des tests unitaires
E: Une valeur any accepte tout et se propage : les erreurs qu'elle cache réapparaissent à l'exécution. unknown est l'alternative sûre : on doit vérifier le type avant de s'en servir. L'option noImplicitAny refuse les any implicites.

@006
Q: Quelle différence entre unknown et any ?
C: unknown oblige à vérifier le type avant usage
W: unknown accepte moins de valeurs que any
W: any oblige à vérifier le type avant usage
W: unknown est un simple alias de any
E: Les deux acceptent n'importe quelle valeur. Avec unknown, appeler une méthode ou lire une propriété est refusé tant qu'un test (typeof, instanceof, validation) n'a pas précisé le type. C'est le bon type pour une donnée reçue d'une API.

@007
Q: Que décrit cette interface ?

W: Une table de base de données Utilisateur

E: Une interface décrit la forme attendue d'un objet ; le point d'interrogation rend email facultatif. Elle disparaît à la compilation : aucun code n'est généré. TypeScript compare les formes, pas les noms : tout objet de la bonne forme convient.
```typescript
interface Utilisateur {

```

@010

E: ?? ne remplace que null et undefined : 0 est conservé. L'opérateur ||, lui, remplace toute valeur fausse, y compris 0 et la chaîne vide : remise || 10 donnerait 10, un bogue classique pour une remise nulle.

@028

E: Après typeof valeur === "string", TypeScript réduit le type de string | number à string dans ce bloc : on peut appeler toUpperCase sans erreur. C'est le rétrécissement de type, aussi obtenu avec instanceof ou in.
```typescript
function afficher(valeur: string | number) {

}
```

@030

```typescript
switch (paiement.type) {
  case "carte": return payerParCarte(paiement);
  case "virement": return payerParVirement(paiement);
  default: {
    const impossible: never = paiement;
    return impossible;
  }
}
```
