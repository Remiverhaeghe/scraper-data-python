@001
Q: À quoi sert la ligne <!DOCTYPE html> placée en tête d'une page ?
C: Elle fait afficher la page en mode standard plutôt qu'en mode de compatibilité
W: Elle charge la dernière version du moteur HTML depuis le site du W3C, puis la met en cache
W: Elle déclare la langue du document
W: Elle remplace la balise <html>
E: Sans doctype, les navigateurs passent en mode « quirks » et reproduisent des comportements anciens : modèle de boîte d'Internet Explorer 5, hauteurs de tableaux différentes. La forme courte <!DOCTYPE html> suffit en HTML5, sans référence à une DTD.
R: MDN : mode quirks et mode standard | https://developer.mozilla.org/fr/docs/Web/HTML/Quirks_Mode_and_Standards_Mode

@002
Q: Quelle balise contient le contenu principal et propre à une page, à raison d'un seul visible à la fois ?

W: <section>
W: <body>

E: <main> exclut ce qui se répète d'une page à l'autre (en-tête, navigation, pied de page). Les lecteurs d'écran proposent d'y sauter directement. <article> désigne un contenu autonome, réutilisable ailleurs (billet, fiche produit), et une page peut en contenir plusieurs.

@004

@005

@007

@008
Q: Quelle différence entre un id et une classe ?
C: Un id est unique dans la page, une même classe peut être portée par plusieurs éléments
W: Un id ne sert qu'au JavaScript et une classe qu'au CSS
W: Une classe est prioritaire sur un id dans la cascade
W: Un élément ne peut porter qu'une seule classe, mais plusieurs id séparés par des espaces
E: Un id sert d'ancre (#contact), de cible à for ou aria-labelledby. Pour le style, on préfère les classes : un sélecteur d'id a une spécificité très forte qui rend les surcharges difficiles. Un élément peut porter plusieurs classes séparées par des espaces.

@009

@010
Q: Dans le modèle de boîte CSS, quel est l'ordre des couches, de l'intérieur vers l'extérieur ?
O: content : le contenu
O: padding : la marge intérieure
O: border : la bordure
O: margin : la marge extérieure
E: Le fond (background) s'étend sous le padding et la bordure, jamais sous la marge. Les marges verticales de deux blocs voisins fusionnent (margin collapsing), ce qui surprend souvent : 20 px et 30 px donnent 30 px d'écart, pas 50.

@011
Q: Avec box-sizing: content-box, une boîte a width: 200px, padding: 10px et border: 2px. Quelle largeur occupe-t-elle à l'écran, en pixels, hors marges ?
N: 224
U: px
E: En content-box, width ne compte que le contenu : 200 + 2 × 10 + 2 × 2 = 224 px. Avec box-sizing: border-box, la boîte ferait 200 px et le contenu se réduirait à 176 px, d'où la règle *, *::before, *::after { box-sizing: border-box; } présente dans la plupart des feuilles de base.

@012

@030
Q: Que signifie flex: 1 sur les éléments d'un conteneur flex ?
C: Ils se partagent à parts égales l'espace disponible
W: Ils prennent chacun une ligne entière
W: Ils gardent leur taille de contenu sans grandir ni rétrécir, ce qui fige la mise en page

@031

@032

U: px
E: Les deux gouttières prennent 40 px, il reste 760 px pour 4 fractions, soit 190 px par fraction. La colonne de 2fr fait donc 380 px. Les fractions ne se partagent que l'espace laissé par les gouttières et les pistes de taille fixe.

@033

@034
Q: Quand préférer grid à flexbox pour une mise en page ?
C: Quand il faut aligner les éléments à la fois en lignes et en colonnes
W: Quand les éléments doivent se suivre sur une seule ligne, comme une barre d'outils
W: Quand la page doit fonctionner sur mobile

@042
Q: Que fait ce code avec la propriété --couleur-accent ?

@047
Q: Quel CSS produit la compilation de ce code Sass ?
C: .menu a { color: navy; } puis .menu a:hover { color: red; }
W: .menu a { color: navy; } puis .menu a :hover { color: red; }
W: a.menu { color: navy; } puis a.menu:hover { color: red; }
W: .menu { color: navy; } a:hover { color: red; }
E: L'imbrication Sass reproduit le combinateur descendant, et & reprend le sélecteur parent sans espace. Sans &, Sass écrirait « .menu a :hover », qui cible un descendant survolé. Imbriquer plus de trois niveaux produit des sélecteurs longs et trop spécifiques.
```scss
.menu {
  a {
    color: navy;
    &:hover {
      color: red;
    }
  }
}
```

@049
Q: Quelle différence entre un mixin Sass et @extend ?
C: Le mixin recopie ses déclarations là où il est inclus, @extend ajoute le sélecteur à une règle existante
W: Le mixin ne prend pas de paramètres, @extend en accepte
W: @extend copie les déclarations, le mixin regroupe les sélecteurs
W: Les deux produisent exactement le même CSS, seule la syntaxe diffère entre les versions de Sass
E: @include bouton($couleur) duplique les déclarations, ce qui se compresse bien en gzip. @extend .base regroupe les sélecteurs (.base, .alerte { … }) mais peut produire des combinaisons inattendues et ne traverse pas les media queries. On réserve @extend aux placeholders %nom.
