@062

E: Le rapport vaut (L1 + 0,05) / (L2 + 0,05), avec L1 la plus claire : 1,05 / 0,23 ≈ 4,57. Le gris passe donc le niveau AA pour le texte courant, de peu. Le 0,05 représente la lumière ambiante réfléchie par l'écran, et donne au noir pur un rapport maximal de 21 avec le blanc.
R: W3C : définition du rapport de contraste | https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio

@090
Q: Que permet subgrid dans cet extrait ?
C: Les cartes reprennent les lignes de la grille parente, donc titres, textes et boutons s'alignent d'une carte à l'autre
W: Une grille de secours pour les navigateurs anciens
W: Une grille plus petite qui se répète dans chaque cellule
W: L'imbrication de grilles indépendantes dans la cellule, chacune avec ses propres lignes de départ
E: Sans subgrid, chaque carte a sa propre grille : un titre sur deux lignes décale les boutons de cette carte seulement. Avec grid-template-rows: subgrid, la carte s'étend sur trois lignes du parent et ses enfants s'y placent, dimensionnées par le plus grand contenu de la rangée.
```css
.cartes { display: grid; grid-template-columns: repeat(3, 1fr); grid-auto-rows: auto; }
.carte  { display: grid; grid-row: span 3; grid-template-rows: subgrid; }
```

@091

C: Le navigateur saute le calcul de mise en page et la peinture des sections non visibles
W: Les sections sont retirées du DOM et rechargées depuis le serveur à l'approche

@092
Q: Une politique de sécurité CSP stricte bloque les attributs style="" écrits dans le HTML. Quelle solution respecte la politique sans l'affaiblir ?

@093

@098
Q: Un menu déroulant personnalisé reçoit role="menu". Pourquoi est-ce souvent une erreur pour une navigation de site ?
C: Le rôle menu promet une navigation aux flèches comme dans un logiciel, que le code ne fournit généralement pas
W: role="menu" n'existe pas dans ARIA
W: Il empêche l'affichage du menu sur mobile
W: Il rend les liens du menu invisibles pour les moteurs de recherche, qui ignorent alors la navigation
E: Le lecteur d'écran change de mode et attend les flèches, Origine et Fin ; si seul Tab fonctionne, l'utilisateur est perdu. Pour une navigation, une liste de liens dans <nav> et un bouton aria-expanded qui l'ouvre suffisent. Le guide APG du W3C décrit le comportement de chaque rôle complexe.
R: W3C : guide des pratiques ARIA (APG) | https://www.w3.org/WAI/ARIA/apg/

@100
Q: Une page passe l'audit Lighthouse à 100 en accessibilité. Que peut-on en conclure ?
C: Les contrôles automatisables passent, mais il reste à vérifier à la main le clavier, le sens des textes et les parcours
W: La page est conforme au RGAA et aux WCAG
W: La page n'a plus besoin d'être testée par des utilisateurs
W: La page est utilisable au lecteur d'écran, puisque Lighthouse simule NVDA pendant son audit
E: Lighthouse s'appuie sur axe et ne voit que ce qui se mesure : un alt présent, un contraste, un nom accessible non vide. Il ne sait pas si l'alt décrit bien l'image ni si l'ordre de lecture a un sens. Une déclaration de conformité suppose un audit complet des critères sur un échantillon de pages.
