@051
Q: Pourquoi cette hiérarchie enfreint-elle le principe de substitution de Liskov ?
C: Un Carre change aussi la hauteur quand on change sa largeur, ce qu'un Rectangle ne fait pas
W: Un Carre ne peut pas hériter d'une classe qui a plus de deux attributs privés
W: Les méthodes de Carre doivent être déclarées finales pour respecter le principe
W: Un Carre devrait implémenter une interface plutôt qu'étendre la classe Rectangle
E: Un code qui fixe largeur 4 et hauteur 5 attend une aire de 20 et obtient 25 avec un Carre. Une sous-classe doit tenir les promesses de sa classe parente ; ici, deux classes sans héritage, ou des objets immuables, règlent le problème.
```java
class Carre extends Rectangle {
    @Override
    void setLargeur(int l) { super.setLargeur(l); super.setHauteur(l); }
    @Override
    void setHauteur(int h) { super.setLargeur(h); super.setHauteur(h); }
}
```
