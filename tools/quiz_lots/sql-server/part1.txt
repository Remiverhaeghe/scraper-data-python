@010

@020

@024

@025

@026

@027
Q: Qu'est-ce qu'une transaction ?
C: Un ensemble d'opérations validé ou annulé en bloc
W: Une requête qui s'exécute plus vite qu'une autre
W: Une copie de la base gardée en mémoire vive
W: Un déclencheur qui s'exécute à heure fixe
E: Entre BEGIN TRANSACTION et COMMIT, toutes les modifications sont validées ensemble ; ROLLBACK les annule toutes. Un virement débite un compte et en crédite un autre : sans transaction, une panne entre les deux ferait disparaître de l'argent.

@028
Q: Que garantit ce bloc si le second UPDATE échoue ?
C: Le premier UPDATE est annulé, aucun compte n'est modifié
W: Le premier UPDATE reste appliqué, seul le second est perdu
W: Les deux UPDATE sont rejoués jusqu'à ce qu'ils réussissent
W: La base est restaurée à la dernière sauvegarde complète
E: Une erreur dans le TRY saute au CATCH, qui annule la transaction : le virement est tout ou rien. XACT_ABORT ON garantit en plus l'annulation sur les erreurs qui ne passent pas par le CATCH. THROW renvoie l'erreur à l'application, qui doit savoir que l'opération a échoué.
```sql
SET XACT_ABORT ON;
BEGIN TRY
    BEGIN TRANSACTION;
    UPDATE Compte SET Solde = Solde - 100 WHERE Id = 1;
    UPDATE Compte SET Solde = Solde + 100 WHERE Id = 2;
    COMMIT;
END TRY
BEGIN CATCH
    IF @@TRANCOUNT > 0 ROLLBACK;
    THROW;
END CATCH;
```

@029
Q: Associer chaque propriété ACID à sa garantie.

P: Cohérence => les règles de la base sont respectées
P: Isolation => les transactions ne se gênent pas
P: Durabilité => ce qui est validé survit à une panne
E: SQL Server assure la durabilité en écrivant d'abord dans le journal avant de confirmer le COMMIT. L'isolation se règle par les niveaux d'isolation, du plus permissif (READ UNCOMMITTED) au plus strict (SERIALIZABLE), avec un compromis entre cohérence et concurrence.

@034

@046
Q: Pourquoi un index accélère-t-il une recherche par nom de client ?
C: Le moteur trouve les lignes sans parcourir toute la table
W: L'index copie la table en mémoire vive en permanence
W: L'index supprime les doublons de la colonne indexée
W: L'index compresse la table pour qu'elle se lise plus vite
E: Un index est une structure triée, un arbre B, qui mène directement aux lignes cherchées, comme l'index d'un livre. Sans index, SQL Server lit toute la table (Table Scan ou Clustered Index Scan). Chaque index ralentit en revanche les insertions et mises à jour.

@047
Q: Quelle différence entre un index cluster et un index non cluster ?
C: Le cluster ordonne la table, l'autre est à part
W: Le cluster est stocké sur un autre serveur, le non cluster en local
W: Le non cluster ordonne la table, le cluster est une copie
W: Une table peut avoir plusieurs index cluster et un seul non cluster
E: Une table n'a qu'un index cluster, souvent la clé primaire : ses feuilles sont les lignes de données. Les index non cluster, jusqu'à 999, contiennent les colonnes indexées et un pointeur vers la ligne. Un identifiant croissant fait un bon index cluster : les insertions vont à la fin.

@048
Q: Que fait cette commande ?
C: Elle crée un index sur la colonne Nom de la table Client
W: Elle crée une colonne Nom indexée dans la table Client
W: Elle trie physiquement la table Client par nom
W: Elle crée une contrainte d'unicité sur le nom
E: CREATE INDEX crée par défaut un index non cluster ; il accélère les recherches et tris sur Nom. Pour interdire les doublons, on écrit CREATE UNIQUE INDEX. Le nom IX_Table_Colonne est une convention courante qui aide à s'y retrouver.
```sql
CREATE INDEX IX_Client_Nom ON dbo.Client (Nom);
```

@049
Q: Pourquoi cette requête ne peut-elle pas utiliser l'index sur DateCommande ?
C: La fonction appliquée à la colonne empêche la recherche dans l'index
W: Les index ne fonctionnent jamais sur des colonnes de type date
W: YEAR() renvoie une chaîne et non un nombre entier
W: L'index n'est utilisé que si la requête trie par date
E: Une fonction sur la colonne indexée rend la condition non « sargable » : le moteur doit calculer YEAR() pour chaque ligne. On réécrit en intervalle : WHERE DateCommande >= '2026-01-01' AND DateCommande < '2027-01-01', qui permet une recherche dans l'index (Index Seek).
```sql
SELECT * FROM Commande
WHERE YEAR(DateCommande) = 2026;
```

@050
Q: Qu'est-ce qu'une table temporaire #Panier ?
C: Une table de tempdb propre à la session
W: Une table partagée par toutes les sessions jusqu'au redémarrage
W: Une table supprimée dès la fin de chaque instruction
W: Une vue en lecture seule sur une table existante
E: Une table #locale disparaît à la fin de la session ou de la procédure qui l'a créée ; ##globale est visible de toutes les sessions. Elle accepte index et statistiques, utile pour découper un traitement complexe. Une variable table @t, plus légère, n'a pas de statistiques complètes.
