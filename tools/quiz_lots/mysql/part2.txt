@051
Q: Quel est le niveau d'isolation par défaut d'InnoDB ?
C: REPEATABLE READ
W: READ COMMITTED
W: READ UNCOMMITTED
W: SERIALIZABLE
E: En REPEATABLE READ, une transaction relit toujours les mêmes valeurs grâce à une vue cohérente prise à sa première lecture. InnoDB y ajoute des verrous d'intervalle (gap locks) qui empêchent la plupart des lignes fantômes. Beaucoup d'autres bases, comme PostgreSQL ou SQL Server, sont en READ COMMITTED par défaut.

@052

W: Elle lit la ligne sans aucun verrou
W: Elle copie la ligne dans une table temporaire
E: La ligne lue est verrouillée en écriture : une autre transaction qui veut la modifier, ou la lire avec FOR UPDATE, attend. On l'utilise pour réserver un stock : lire la quantité, vérifier, décrémenter, sans qu'une commande concurrente passe entre les deux. Depuis MySQL 8.0, NOWAIT et SKIP LOCKED évitent d'attendre.
```sql
START TRANSACTION;
SELECT quantite FROM stock WHERE produit_id = 12 FOR UPDATE;
```

@064


E: Le regroupement par e-mail puis le filtre sur les groupes de plus d'une ligne isolent les doublons. DISTINCT les masquerait au lieu de les montrer. Une fois nettoyés, un index UNIQUE empêche qu'ils reviennent. La collation insensible à la casse compte « A@x.fr » et « a@x.fr » comme un doublon.
```sql
SELECT email, COUNT(*) AS nb
FROM client
GROUP BY email
HAVING COUNT(*) > 1;
```

Q: Pourquoi chiffrer les connexions à MySQL quand l'application et la base sont sur des serveurs différents ?
